# Human skill

The goal of the skill form is to be simple and easy to understand so that skill:
* is minimalistic - means you cannot remove anything there without changing what the skill produces or way of reasoning. In practice it means you must remove repetitions, reassurances and things the model already knows.
* easy to understand for the human - no jargon, empathetically take into account that human may not know what you know
* is final snapshot - does not have reference to previous version, mentioning modification strategies, refering to any discussion or thinking process
* declarative - don't try do describe things in details, especially when llm model quite likely has all needed knowledge. Describe rules when they are very specific to the described problem, not being known facts

# Conventions
Main skill contents is defined in human language and don't refer to technical aspects of skill execution which is defined here in this file.

## Structured inputs and output
Inputs and outputs are defined in `./scripts/contracts.py`

Every such structured input or output should be validated with Pydantic validate to ensure correctness and saved serialized as yaml file for audit log.

### Beginning (input data) and end (output data) of skill

#### Input
Declare input typed data at the beginning of the skill file.
Input (→ `ReviewContext`) 
or for more inputs
Input (request → `ReviewContext`, policy → ReviewPolicy(`policy.yaml`))

#### Output
Declare output typed data at the end of the skill file.
Output (→ ReviewResult(`review-result.yaml`))

### Declare the stage result at the end

```markdown
(→ `ReviewContext`)
```

Input should be inferred from skill text context - usually output of previous step(s) or skill input.

## Subagents
Subagents are defined with human language. 

### Declaring agents 
Here is example of recommended way how they should be defined:

```markdown
Subagent: Evidence Reviewer (→ `EvidenceReview`)

Using the review context, check whether every proposal claim is supported by
available evidence. Identify unsupported claims and missing evidence.
```

Input of the subagent should be inferred from the context of the skill text and usually is output of one of the previous steps. Input should be passed in form of serialized and saved yaml file from pydantic model instance. The same for output. Communication is always through files to maximize reliability.

### Parallel execution
Subagents can be used to parallelize execution. It can be defines in skill in this way eg.

```markdown
Review the proposal using these two subagents in parallel:

Subagent: Evidence Reviewer (→ `EvidenceReview`)

Check whether every material claim is supported.

Subagent: Policy Reviewer (→ `PolicyReview`)

Check whether the proposal satisfies every applicable policy requirement.
```

# Patterns
Additional patterns can be reffered that ortogonally add additional behaviour the the skill.

## Workspace pattern
Every execution of the skill creates a workspace named: `./.workspaces/<skill-name>/<timestamp-id-yyyy-MM-dd-HH:mm:ss>/` unless defined in other way in skill.
Every file generated by the skill by default is output to this directory especially Pydantic serialized models unless skill states otherwise.
