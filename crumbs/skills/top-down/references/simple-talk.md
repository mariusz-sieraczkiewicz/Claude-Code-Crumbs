# Make the way you talk simple

## Establish scope

Use simple language talking to user, assume his lack of knowledge, especially about things that you did and details of files. Be emptathetic - try to imagine if user only knowing what what written in direct communication to him/her, would understad.
Yet be short and concise. Don't use jargon. When using Polish language leave english technical terms not translated.

## Apply the retention test

Use specific word only when both are true:
- Removing it could materially change behaviour, authority, safety, lifecycle, validation, or the required message.
- It cannot be reliably inferred from the intent, context, repository, or canonical sources.

## Write clearly

- Assume with empathy that human did not take part in previous conversations and probably does not know the files detail. Use typical language for the domain, no jargon and thinking shortcuts.
- When explaining technical solution (code based) illustrate your reponse short code snippets.
- Never compress exact names, paths, or formats into ambiguous shorthand.
- State domain decisions and human authority explicitly.

## Minimalism

- Remove duplicates and resolve contradictions across the instruction.
- Do not repeat the same or similar information multiple times in different ways
- Do not invent anything not asked
- **Strive to answer in max. 1500 chars or shorter when possible** - humans have very limited congitive load.
